# نصب ZDIS PHP روی cPanel — نسخهٔ آزمایشی ۰٫۲

این بسته یک پورت مستقل از Realjustawall/zdis است. مخزن اصلی تغییر نکرده است.
قبل از نصب، PORTING-STATUS.md را بخوانید: بخش اصلی چت قابل اجراست، اما همهٔ قابلیت‌های بک‌اند Node.js منتقل نشده‌اند. این بسته جایگزین کامل و تأییدشدهٔ نسخهٔ اصلی برای محیط تولید نیست.

## پیش‌نیازها

- PHP 8.2 یا جدیدتر با PDO، pdo_mysql، mysqlnd، mbstring، fileinfo، cURL و OpenSSL؛ GD با FreeType برای بنر خوش‌آمدگویی.
- MySQL 8 یا MariaDB 10.6+ و InnoDB با utf8mb4. آزمون عملی با PHP 8.3 و MariaDB 10.11 انجام شده؛ MySQL 8 جداگانه تست نشده است.
- Apache 2.4 یا LiteSpeed با پشتیبانی از قواعد .htaccess و mod_rewrite.
- HTTPS معتبر. Web Crypto، میکروفن و دوربین به محیط امن مرورگر نیاز دارند.
- دسترسی نوشتن PHP به پوشهٔ storage؛ از مجوز 777 استفاده نکنید.
- زمان‌بندی Cron هر دقیقه برای انتشار پیام‌های زمان‌بندی‌شده، تحویل صف وب‌هوک، نگهداری ربات‌ها و پاک‌سازی داده‌های موقت.

Node.js و Composer هنگام اجرای سایت لازم نیستند؛ رابط از قبل بیلد شده است.

## چیدمان پیشنهادی برای دامنه یا ساب‌دامنه

۱. پوشهٔ application داخل ZIP را در مسیری مانند `/home/USER/zdis-private` استخراج کنید.
۲. Document Root دامنه یا ساب‌دامنه را روی `/home/USER/zdis-private/public` بگذارید.
۳. در MySQL Database Wizard یک دیتابیس و کاربر بسازید؛ کاربر را با مجوزهای دیتابیس به همان دیتابیس اضافه کنید. نام کامل معمولاً پیشوند حساب cPanel دارد.
۴. `config.example.php` را به `config.php` کپی کنید و DSN، نام کاربر و رمز دیتابیس را وارد کنید. `origin` باید دقیقاً شبیه `https://chat.example.com` باشد؛ بدون اسلش انتهایی و بدون مسیر.
۵. `app_key` را یک رشتهٔ تصادفی ۶۴ نویسه‌ای هگز بگذارید. اگر ترمینال دارید:

```sh
php -r 'echo bin2hex(random_bytes(32)), PHP_EOL;'
```

۶. برای نصب تحت وب، `setup_token` را هم یک مقدار تصادفی حداقل ۳۲ نویسه‌ای بگذارید. مسیر `https://chat.example.com/setup.php` را باز کنید. توکن، نام کاربری، ایمیل و رمز مدیر را وارد کنید؛ جداول و مدیر اولیه ایجاد می‌شوند.
۷. پس از نصب، setup_token را خالی کنید. وجود هر حساب، نصب‌کننده را قفل می‌کند. رمز پیش‌فرض مدیر در بسته وجود ندارد.
۸. از `/` وارد شوید. ثبت‌نام عمومی پیش‌فرض بسته است؛ مدیر می‌تواند آن را در تنظیمات فعال کند.

`config.php`، `app`، `bin`، `storage` و فایل SQL باید خارج از Document Root باشند. فقط پوشهٔ public وب‌دسترسی دارد. اگر این چیدمان را رعایت کنید، داده‌های آپلودشده فقط از مسیرهای کنترل‌شدهٔ PHP قابل دریافت‌اند.

## نصب روی دامنهٔ اصلی با public_html ثابت

۱. فایل‌ها و پوشه‌های داخل `application/public`، از جمله `.htaccess` و `.user.ini` را داخل public_html کپی کنید.
۲. سایر بخش‌های application را بیرون public_html، مثلاً `/home/USER/zdis-private` قرار دهید.
۳. در `public_html/paths.php` مسیر برگشتی را تغییر دهید:

```php
return '/home/USER/zdis-private';
```

۴. بقیهٔ مراحل تنظیم دیتابیس و setup.php همان مراحل بالاست. نیازی به قرار دادن کد خصوصی کنار index.php نیست.

این نسخه برای ریشهٔ دامنه/ساب‌دامنه تنظیم شده است. نصب داخل مسیر `/chat/` بدون تغییر base و مسیرهای API پشتیبانی نمی‌شود.

## نصب از ترمینال به جای نصب تحت وب

پس از تنظیم config.php:

```sh
cd /home/USER/zdis-private
php bin/install.php
```

نام کاربری، ایمیل و رمز مدیر را وارد کنید. ترمینال خصوصی استفاده کنید؛ ورودی رمز این ابزار مخفی نمی‌شود. به‌جای تایپ تعاملی می‌توان رمز را در متغیر محیطی ZDIS_ADMIN_PASSWORD قرار داد؛ رمز را داخل فایل عمومی یا تاریخچهٔ فرمان ذخیره نکنید. لازم نیست setup_token فعال باشد.

## Cron

در cPanel → Cron Jobs هر دقیقه این فرمان را با PHP سازگار با سایت اجرا کنید:

```sh
/usr/local/bin/php /home/USER/zdis-private/bin/cron.php
```

الگوی زمان `* * * * *` است. مسیر PHP در بعضی هاست‌ها متفاوت است؛ نسخهٔ CLI باید ماژول‌های لازم را داشته باشد. بدون Cron، پیام زمان‌بندی‌شده خودکار منتشر نمی‌شود. زمان دقیق انتشار به اجرای Cron وابسته است و می‌تواند حدود یک دقیقه تأخیر داشته باشد.

## فایل‌ها و تماس

- حد آپلود در تنظیمات برنامه و مقادیر PHP upload_max_filesize / post_max_size را هماهنگ کنید. آپلودهای بزرگ رابط با قطعه‌های ۱ مگابایتی ارسال می‌شوند.
- فایل‌ها خارج از وب‌روت ذخیره می‌شوند و PHP عضویت فرستنده/گیرنده را هنگام دریافت دوباره کنترل می‌کند.
- اسکن آنتی‌ویروس و تبدیل رسانه در این پورت وجود ندارد. scanStatus مقدار not_configured دارد.
- تماس به‌صورت WebRTC mesh است؛ PHP فقط سیگنالینگ را با درخواست‌های کوتاه جابه‌جا می‌کند. سقف هر اتاق ۸ نفر است.
- برای شبکه‌هایی که STUN کافی نیست، TURN خارجی خودتان را در ice_servers تنظیم کنید. مثال:

```php
'ice_servers' => [
  ['urls' => 'stun:stun.l.google.com:19302'],
  ['urls' => 'turn:turn.example.com:3478', 'username' => 'YOUR_USER', 'credential' => 'YOUR_PASSWORD'],
],
```

اعتبارنامهٔ ثابت TURN به کاربران احرازشده ارسال می‌شود؛ از آن برای حساب مدیریتی استفاده نکنید. خود هاست اشتراکی در این بسته سرویس TURN یا SFU اجرا نمی‌کند. آزمون مرورگر محلی، تضمین تماس از همهٔ شبکه‌های اینترنت نیست.

## پشتیبان‌گیری و جابه‌جایی

از دیتابیس، storage و config.php به‌صورت هماهنگ پشتیبان بگیرید. app_key برای بازیابی کلیدهای ذخیره‌شده لازم است. ابزار تبدیل دیتابیس SQLite/Postgres نسخهٔ اصلی به این اسکیمای MySQL در این بسته وجود ندارد؛ نصب فعلی برای دیتابیس تازه است.

## خطایابی

- `/api/health` باید JSON با ok=true نشان دهد.
- خطای 503: config.php یا مسیر appRoot تنظیم نشده است.
- خطای 500: PHP error log هاست، اطلاعات دیتابیس و ماژول‌ها را بررسی کنید؛ جزئیات حساس برای کاربر چاپ نمی‌شوند.
- API به‌جای JSON صفحهٔ HTML می‌دهد: وجود .htaccess، Show Hidden Files در File Manager و فعال‌بودن rewrite را بررسی کنید.
- CSRF/Origin خطا دارد: origin تنظیمات، HTTPS و دامنهٔ استفاده‌شده باید یکسان باشند.
- خطای 501: قابلیت مربوط هنوز به PHP منتقل نشده؛ فهرست در PORTING-STATUS.md است. این خطا به معنی موفقیت عملیات نیست.

تست روی cPanel واقعی و تنظیمات اختصاصی شرکت هاست در این محیط انجام نشده است.


## API و وب‌هوک

مدیر می‌تواند feature_api_keys و feature_webhooks را در تنظیمات فعال کند. Token و secret فقط در زمان ایجاد نمایش داده می‌شوند. برای درخواست Bearer، scope read/write/admin بررسی می‌شود؛ درخواست حساب مرورگری همچنان CSRF لازم دارد. وب‌هوک خروجی به cURL و Cron نیاز دارد. مقصدهای خصوصی و loopback در تولید رد می‌شوند؛ گزینهٔ test_allow_local_http صرفاً برای محیط تست جداشده است و نباید در config تولید فعال شود. پاسخ وب‌هوک موفق باید 2xx باشد. گیرنده باید delivery ID را برای حذف اثر تکراری نگه دارد. صف پس از ۵ تلاش ناموفق failed می‌شود؛ پنل جامع صف/DLQ هنوز منتقل نشده است.

بنر ربات به GD/FreeType و فونت همراه بسته نیاز دارد. شکل و رندر فارسی بنر هنوز معادل کامل نسخهٔ اصلی نیست. SSO، SMTP/Push، LiveKit و S3 در این نسخه فعال نیستند؛ دیدن صفحات آن‌ها در رابط اصلی به معنی آماده‌بودن سرویس نیست.
